# Decisions

Append-only. Newest at the bottom. Format: date · decision · why · rejected.

- **2026-10-24 · Shared Rust core + fully native shells.** The correctness-critical engine is written once; the UI is where nativeness lives, so it is never shared. Rejected: spec-only with five engines (five sets of integrity bugs); cross-platform UI toolkits (not native).
- **2026-10-24 · Name: Dhow.** Cargo vessel between any shores; fits the expansion to device-to-device transfer. Checked crates.io, npm, GitHub, App Store, general web: only an unrelated small npm SSG. Rejected: Ferry (RustFerry/cargo-ferry, FileFerry, `ferry` crate), Portage (Gentoo), Peyk (UK courier company), Chapar (API testing tool), Tug (too close to "Tur", an existing Rust download manager), Caravan, Hauler (Rancher).
- **2026-10-24 · License: GPL-3.0-or-later for everything, including the core.** Keeps the open-source promise and blocks proprietary forks. Rejected: MIT/Apache core (would let the engine be lifted into closed products).
- **2026-10-24 · SQLite for index + per-download binary sidecar journal as the integrity authority.** DB gives cheap cross-download queries; the sidecar keeps fsync discipline local and makes every download self-describing. Rejected: DB-only (fsync coupling, download not recoverable if DB lost); sidecar-only (slow list queries).
- **2026-10-24 · Oldest-first connection allocation with one-connection minimum for newcomers.** Matches the requested politeness ("new downloads wait for old ones") while keeping every download visibly alive. Rejected: strict FIFO (new downloads appear dead); round-robin fairness (defeats the point).
- **2026-10-24 · Single main window with a detail pane; speed chart only in the detail pane.** Matches every platform's current conventions. Rejected: window per download (IDM-era), chart in the main list (clutter).
- **2026-10-24 · Moved-file tracking only where the OS provides it for free (macOS/iOS bookmarks, Windows file IDs).** Rejected: Linux/Android scanning or fanotify watchers (cost, permissions, idle violation).
- **2026-10-24 · Proxy/VPN: detect and display, optionally use system proxy or custom; never modify OS settings.** Rejected: anything requiring elevated privileges.
- **2026-10-24 · Platform order: macOS → Linux → Windows → Android → iOS.** Maintainer is on macOS; Linux shell is pure Rust and validates the core API without an FFI layer; Windows needs the C ABI; mobile last because background constraints are hardest.
- **2026-10-24 · JSON over the C ABI for the Windows shell.** Stability over micro-performance for a UI boundary that moves a few events per second. Revisit only with profiling evidence.
- **2026-10-24 · Browser extension and clipboard watching deferred to M9.** Glue, not core. Rejected: v1 inclusion (delays the engine).
- **2026-10-24 · Prior art noted, not copied.** aria2's per-host limits and `tur-rs`'s range-stealing scheduler informed §4.3 and §10.2 of the engine spec. No code was read from either while writing the spec; none may be copied while implementing it.
- **2026-10-24 · CLI binary is `dhow`, crate is `dhow-cli`.** ARCHITECTURE §2 and M1.8 already use `dhow add …`; ROADMAP M0 exit text said `dhow-cli --version` and was corrected. Rejected: binary named `dhow-cli` (clunky for the reference client every test types).
- **2026-10-24 · Cargo workspace lives in `core/`.** Shells are not Cargo crates (except Linux, which can join later). Rejected: workspace at repo root (would pull shells into Cargo's view before they exist).
- **2026-10-24 · Per-PR CI is one Linux runner (fmt, clippy, test); full target matrix only at release time.** Single maintainer builds and uses Dhow locally; macOS/Windows runners are slow and costly for little signal on a pure-Rust core this early. macOS/iOS can't be built from Linux without Apple's SDK. Rejected: full 12-target matrix on every PR.
- **2026-10-24 · `dhow-testserver` speaks hand-rolled HTTP/1.1 on tokio, not axum/hyper.** Its job is to violate HTTP (bytes past `Content-Length`, garbage in ranges, stalled heads), which correct libraries refuse to do. HTTP/2 added only when a test needs it. Rejected: hyper (would need raw-socket escape hatches for every interesting knob).
- **2026-10-24 · Test content is a blake3 XOF stream keyed by seed; spec-tests run the server in-process and the CLI as a subprocess.** Any range is computable without fixtures, expected digests are free, and kill -9 hits only the client. Rejected: fixture files (repo bloat, no arbitrary sizes); server as subprocess (slower, needs a control channel for stateful knobs).
- **2026-10-24 · Logs are synchronous JSON lines, daily files, 7 kept, in the platform log dir.** Crash and kill -9 diagnosis needs the last lines on disk; log volume is low. Rejected: `tracing-appender` non-blocking writer (drops buffered lines on crash, adds a thread); plain-text format (harder to grep by download id).
- **2026-10-24 · Hand-rolled migrations on `PRAGMA user_version`, one transaction per migration; newer DBs refused.** ~30 lines, no dependency, and the rollback guarantee is tested directly. Rejected: `rusqlite_migration`/`refinery` (more surface than the problem needs); a separate `schema.sql` "truth" file (drifts from the migrations).
- **2026-10-24 · Schema v1 adds `position`, `digest`, `size_unverified`, `identity_weak`, `on_complete` and a seeded default queue beyond the abridged ARCHITECTURE list.** Each is required by ENGINE-SPEC (§10.4 Reorder, I8 across restarts since a 206's `Content-Digest` covers only the part, I7/I4 flags, §11 QueueSpec and default queue). Default queue name is NULL so no display string lives in the core.
- **2026-10-24 · Probe sends the 0-0 `GET` whenever `HEAD` doesn't settle size *and* resumability, and on any `HEAD` failure; a setting disables it entirely.** §2.1 (405/501, no length) contradicted §2.3's `Unknown` example (length but no `Accept-Ranges`); S3-style signed URLs answer `HEAD` with 403. The off switch exists for one-shot links, so it also suppresses the fallback. Rejected: literal §2.1 (leaves resumability `Unknown` where one request would settle it).
- **2026-10-24 · Digests from a 206 only via `Repr-Digest`/`Digest`; added `Repr-Digest` (RFC 9530).** `Content-Digest`/`Content-MD5` on a 206 cover the partial body and would cause false `DigestMismatch`. Rejected: trusting any digest header on any response.
- **2026-10-24 · reqwest 0.13 with `rustls` (aws-lc-rs, OS trust store via platform verifier), no default features.** No automatic decompression, no implicit proxy until M3.4. aws-lc-rs cross-compiles less easily than ring; revisit at the first release build for mobile/Windows. Rejected: native-tls (per-platform behavior differences in the integrity path).
- **2026-10-24 · Names are capped at 246 bytes in total, not 255 bytes of stem.** §3 as written allowed names longer than every filesystem's 255-byte limit, and ignored the `.dhow.tmp` suffix compaction appends. Rejected: per-filesystem limits (UTF-8 bytes never undercount NTFS's UTF-16 units, so one limit is safe everywhere).
- **2026-10-24 · Naming fills gaps in §3: strip leading dots, prefix (not strip) Windows reserved names, case-insensitive collisions incl. `.dhow`, compound `.tar.*` extensions, an explicit extension rule, lenient backslash handling in quoted filenames.** Each was unspecified and each changes output; the T-3 table pins them. Rejected: mirroring a particular browser (they disagree with each other).
- **2026-10-24 · Sidecar format v1 gains a header CRC, little-endian integers and strict record validation; replay truncates the invalid tail before appending.** The header had no checksum (a crash during create left an unreadable but plausible header); endianness was unspecified; without truncation, records appended after a torn tail were invisible to the next replay, silently losing committed progress. Rejected: lenient replay that skips bad records and continues (would trust bytes after damage, against I3).
- **2026-10-24 · Writer runs on a dedicated thread per active download, fed by a bounded `flume` channel; preallocation and free space via `fs4`.** Blocking `pwrite`/`F_FULLFSYNC` stay off tokio workers; flume gives async send with backpressure plus `recv_deadline` on the thread, so an idle writer has no timer. fs4's `allocate` is `fallocate`/`F_PREALLOCATE`/`SetFileInformationByHandle` (read before adopting). Rejected: `spawn_blocking` per write (thread-pool churn), `block_in_place` (ties the writer to the multi-thread runtime and stalls a worker), hand-written per-OS preallocation (more unsafe code in core for the same calls).
- **2026-10-24 · Transfer loop: `max_retries` counts failed attempts and progress resets it; requests always go to the original URL; capped 206 ranges are accepted; a 200 at offset 0 is checked against `If-Range` before being treated as "no range support".** T-9a and T-I7 are only both satisfiable with these counting rules; signed redirect targets expire; some servers cap range length; a 200 after a failed `If-Range` is a different file, and treating it as a downgrade would bind the journal to the wrong content. Rejected: exact `Content-Range` match (fails on range-capping servers), requesting `effective_url` (breaks on expiring signed URLs).
- **2026-10-24 · Resume re-probes and checks identity before requesting; reset deletes and recreates both files; at most 3 resets per run; overlap bytes are read before the writer starts.** Catching a changed file at the probe saves a wasted request and covers servers that ignore `If-Range`; recreating is simpler and as safe as truncating in place given the delete order; a reset cap stops endless restarts on servers that change per request. Rejected: truncating the part and rewriting the sidecar header in place (two files mutated non-atomically), reading overlaps through the writer actor (extra message type for a one-time read).
- **2026-10-24 · Blind downloads that did receive a `Content-Length` complete without `SizeUnverified`.** I7 as written would fail them, but the HTTP layer already rejects a short body there, so the size is verified. Rejected: failing such downloads.
